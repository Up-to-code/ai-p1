# Glossary

## Product terms

- **Client**: person or organization receiving work or buying a service.
- **Opportunity**: potential revenue, request, or pipeline item before it becomes
  committed work.
- **Project**: coordinated work with owner, team, status, health, dates, and
  linked tasks/assets/events.
- **Task**: actionable work item with status, priority, assignee, due date, and
  linked records.
- **Calendar event**: scheduled time block linked to records or people.
- **Asset**: reusable file, resource, document, media item, link, or deliverable.
- **Automation rule**: trigger, conditions, and actions that operate on records.
- **Custom field definition**: typed field configuration applied to one or more
  record types.
- **Custom field value**: stored typed value for a custom field definition.
- **Record link**: typed relationship between two Work OS core records.
- **Workspace template**: industry or workflow preset for labels, statuses,
  stages, views, custom fields, and automation recipes.
- **Connector**: external integration that reads, writes, or syncs Work OS data.
- **MCP tool**: tool exposed for agent or partner execution against Work OS data.

## Architecture terms

- **Module**: anything with an Interface and Implementation.
- **Interface**: everything a caller must know to use a Module.
- **Implementation**: code inside the Module.
- **Depth**: leverage hidden behind a small Interface.
- **Seam**: place where behavior can change without editing callers.
- **Adapter**: concrete thing satisfying an Interface at a Seam.
- **Leverage**: what callers get from depth.
- **Locality**: change, bugs, and knowledge concentrated in one place.
