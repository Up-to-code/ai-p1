## Resource server checks

Partner apps call Workspace Hono APIs. Workspace validates issuer, audience, signature, expiry, app approval, organization connection, connection expiry, and scopes before business logic runs.

```bash
curl "$QENTRAH_WORKSPACE_API_URL/api/v1/partner/organizations/org_123/clients" \
  -H "Authorization: Bearer $QENTRAH_ACCESS_TOKEN"
```

## Common errors

- `Bearer token is required.`: send the access token in the Authorization header.
- `Token organization does not match this route.`: the token was granted for a different organization.
- `connection_not_found`: the organization has not authorized this app.
- `connection_expired`: the 14-day authorization has expired.
- `scope_denied`: the token or connection does not include the required scope.

## Example backend call

```ts
import { createQentrahServiceAppClient } from "@qentrah/auth-sdk/partner/service-app";

const qentrah = createQentrahServiceAppClient({
  workspaceBaseUrl: process.env.QENTRAH_WORKSPACE_API_URL!,
  accessToken: "read-from-your-token-store",
});

const clients = await qentrah.read({
  organizationId: "org_123",
  resource: "client",
  input: { limit: 25 },
});
```

Use tokens saved by the SDK callback handler. Do not expose access tokens to browser JavaScript.
