Welcome to the Qentrah Partner Portal. These docs cover the production path for registering an app, requesting review, authorizing a Qentrah organization with the SDK, and calling Workspace APIs from your backend.

<Callout title="Security model">
Partner apps should use `@qentrah/auth-sdk`, request the smallest useful scope set, and keep token exchange, refresh, webhook signing secrets, and token storage on the server.
</Callout>

## What you can build

- Workspace automations that read organization clients, properties, projects, and offers.
- Internal developer tools that act on behalf of a verified organization.
- Server-side API integrations that keep secrets outside the browser.

## Fast implementation

Start with the [SDK installation guide](/docs/sdk-installation). It includes npm, no-build HTTPS script loading, Next.js OAuth routes, webhook verification, service-app calls, and Vercel environment notes.

Use [Developer mode](/docs/developer-mode) when you are testing local callback URLs, preview apps, webhook tunnels, and development tokens before production review.

Use the [AI agent implementation prompt](/docs/ai-agent-implementation) to copy a complete, server-safe brief for adding the SDK button, backend routes, env setup, token storage, webhooks, and Workspace API reads.

## Portal flow

1. Create a partner programmer account.
2. Register an app with a partner app URL, redirect URIs, and scopes.
3. Submit the app for Qentrah review.
4. Send workspace admins through the SDK-powered Authorize with Qentrah button.
5. Call Workspace Hono APIs after the organization authorizes access.
