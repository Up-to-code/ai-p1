---
title: Developer mode
description: Build and test a Qentrah partner integration locally with SDK authorization, webhooks, and service-app calls.
---

Developer mode is for building against local or preview environments before production review. Use the same SDK flow you will use in production, but register local redirect URLs and keep all secrets in local environment variables.

## Local setup

Register a development redirect URI for your app:

```txt
http://localhost:4000/api/qentrah/oauth/callback
```

Use local environment variables:

```bash
QENTRAH_WORKSPACE_API_URL=http://localhost:3000
QENTRAH_CLIENT_ID=partners_client_...
QENTRAH_CLIENT_SECRET=
QENTRAH_WEBHOOK_SECRET=whsec_dev_...
PARTNER_APP_URL=http://localhost:4000
SESSION_SECRET=replace-with-at-least-32-characters
```

Use `QENTRAH_CLIENT_SECRET` only for confidential server-side clients. Public PKCE clients can leave it empty.

## Authorization in developer mode

The browser button should always open your backend start route. Do not build the Qentrah authorization URL in browser code.

```html
<button id="qentrah-authorize">Authorize with Qentrah</button>
<script src="https://cdn.jsdelivr.net/npm/@qentrah/auth-sdk@0.3.2/dist/qentrah-auth.js"></script>
<script>
  window.QentrahAuth.mountAuthorizeButton({
    buttonId: "qentrah-authorize",
    startUrl: "/api/qentrah/oauth/start",
    label: "Authorize with Qentrah"
  });
</script>
```

Your backend handles:

```txt
GET /api/qentrah/oauth/start
GET /api/qentrah/oauth/callback
```

The SDK creates PKCE/state, validates callback state, exchanges the code server-side, and calls your `tokenStore`.

## Session and token storage

For quick local testing, an in-memory store is acceptable. For preview and production, use encrypted cookies, Redis, or your database.

Keep these server-side only:

- `clientSecret`
- access tokens
- refresh tokens
- authorization codes
- webhook signing secrets
- PKCE verifier

## Webhooks in developer mode

Webhook routes must be reachable by Qentrah. For local development, expose your app with a tunnel such as your deployment preview URL, ngrok, Cloudflare Tunnel, or another HTTPS tunnel.

Example webhook endpoint:

```txt
https://your-dev-tunnel.example/api/qentrah/webhooks
```

Next.js webhook route:

```ts
import { createQentrahWebhookHandler } from "@qentrah/auth-sdk/partner/webhooks";

export const runtime = "nodejs";

export const POST = createQentrahWebhookHandler({
  signingSecret: process.env.QENTRAH_WEBHOOK_SECRET!,
  handlers: {
    "client.created": async (event) => {
      console.log("Client created", event.data);
    },
    "client.updated": async (event) => {
      console.log("Client updated", event.data);
    },
    "client.deleted": async (event) => {
      console.log("Client deleted", event.data.id);
    },
  },
});
```

Do not call `request.json()` before verification. The SDK verifies the raw body using `Qentrah-Signature`, `Qentrah-Timestamp`, `Qentrah-Event-Id`, `Qentrah-Event-Type`, and `Qentrah-Delivery-Id`.

## Service-app calls

Use saved server-side tokens from your `tokenStore`:

```ts
import { createQentrahServiceAppClient } from "@qentrah/auth-sdk/partner/service-app";

const qentrah = createQentrahServiceAppClient({
  workspaceBaseUrl: process.env.QENTRAH_WORKSPACE_API_URL!,
  accessToken: savedAccessToken,
});

await qentrah.read({
  organizationId,
  resource: "client",
  input: { limit: 25 },
});
```

Use idempotency keys for write calls during development so retries do not create duplicate data.

## Developer checklist

- Register `localhost` and preview callback URLs before testing.
- Use the SDK or HTTPS script URL for the browser button.
- Keep the OAuth callback route on the backend.
- Store pending authorization state in a server-side session.
- Store tokens server-side, keyed by `organizationId`.
- Expose webhook routes over HTTPS when testing local webhooks.
- Verify webhooks before parsing JSON.
- Use separate development and production client IDs when possible.
- Rotate local secrets if they are pasted into logs, screenshots, or chat.

## Moving to production

Before review, replace local URLs with production URLs:

```bash
QENTRAH_WORKSPACE_API_URL=https://app.qentrah.com
PARTNER_APP_URL=https://partner.example.com
```

Then confirm:

- Production redirect URI is registered exactly.
- Production webhook URL uses HTTPS.
- Production secrets are stored in your hosting provider's protected environment variables.
- Debug logs do not print tokens or webhook secrets.
